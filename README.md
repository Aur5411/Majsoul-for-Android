# 雀魂麻将 · majsoul

面向「雀魂」网页版的第三方 Android 辅助客户端。把雀魂官网装进一个 WebView 壳里，本地跑 Mortal 神经网络算出打牌建议，再把「该切哪张牌」直接画在牌桌上。

> **非官方、非授权工具，仅供技术研究学习。** 雀魂官方禁止使用第三方辅助，使用可能导致账号被永久封禁，风险自负。

> 本仓库为 APK 反编译产物（smali）的留存与维护仓库，用于记录与分发全皮肤更新相关的修复改动。
> 仓库内所有内容均来自对已发布 APK 的静态分析，不含官方源码，与雀魂官方及原开发者无任何关联。
> 若相关权利人认为本仓库内容侵犯其权益，请通过 Issues 联系，将第一时间处理。

## 主要功能

### 🐱 切牌推荐（小猫推荐）
核心功能。牌桌上浮出猫咪造型的标记，直接指出该打哪一张，并附带置信度。支持四麻 / 三麻，能识别吃、碰、杠、拔北、立直等操作时机。标记跟随游戏引擎的实时牌位计算，吃碰杠后的手牌重排、庄家开局第 14 张牌的入场动画都能跟住，不会错位。

### 🤖 自动打牌
按 AI 推荐自动出牌。切牌间隔可配置，并带随机化，避免过于机械的固定节奏。

### 🪟 悬浮窗
系统级前台悬浮窗，随时显示当前状态（等待登录 / 等待对局 / 对局中）与切牌推荐。支持横向、竖向两种紧凑布局，长按可关闭。悬浮窗开关不影响牌桌上的推荐标记。

### 🎨 全皮肤解锁
解锁全部角色皮肤。皮肤数据随包预置在 `assets/` 内，开箱即用；也支持在线增量更新，更新失败会自动保留原有可用版本。

### 🖥️ 画质 / 帧率设置
提供 720P / 1080P 两档渲染画质与帧率调节。开高画质会明显增加耗电与发热，性能较弱的机型建议保持默认档。

### 🔐 授权与更新
十位卡密激活，可查看有效期与续费，内置版本检查与更新。

### 🟢 不更新版 —— 推荐优先使用

`Majsoul-NO-UPDATE-v9.9.9.apk`

- **完全不发起任何网络请求**，启动后不检查更新、不下载任何东西。
- 直接使用 APK 内预置的完整皮肤数据，功能不打折。
- **界面不显示任何检查 / 更新按钮**，进入后直接提示「已是最新版」。
- 不可能出现「网络错误」，也不可能因为更新而闪退。

适用于网络环境受限、只想要一个稳定可用版本的场景。

### 🔵 自动更新版

`Majsoul-AUTO-UPDATE-v9.9.9.apk`

- **每次冷启动自动检查一次**（彻底退出 App 后重开才触发；单纯刷新网页不会重复检查）。
- **全过程后台静默执行**：检查、下载、安装一气呵成，无需任何点击。
- 检测到**不是最新版本就立即自动更新，失败则持续重试直到成功**，不需要手动盯着。
- **网络错误自动切换线路**：内置多条代理线路，连续失败自动轮换到下一条继续试。
- 重试采用**指数退避**（3s → 6s → 12s → 24s → 30s 封顶），不会疯狂刷请求。
- **界面不显示任何检查 / 更新按钮**，状态仅在顶部状态栏以文字提示。
- 更新期间不会重复触发，也不会因重复点击产生异常。

适用于希望自动跟进最新皮肤数据的用户。

**自动重试与换线**

| 轮次 | 线路 | 退避等待 | 说明 |
|---|---|---|---|
| 第 1 次 | `gh-proxy.com` | — | 首选线路 |
| 失败 1 次 | 沿用当前线路 | 3s | 偶发抖动，原线路重试 |
| 失败 2 次 | **切换到下一条线路** | 6s | 连败判定为线路问题，自动换线 |
| 失败 3 次 | 继续轮换 | 12s | 环形轮换，永不越界 |
| 失败 4 次+ | 继续轮换 | 24s / 30s 封顶 | 一直试到成功 |

线路池（环形轮换）：`gh-proxy.com` → 直连 → `ghproxy.net`

**冷启动门控**

`DGStart` 用进程级静态标志实现：进程启动后第一次进入触发检查；
之后无论刷新网页 / 重建 Activity 多少次都不再触发；彻底退出后再打开重新触发一次。

**状态提示一览（自动更新版）**

界面上**没有任何按钮**，状态只通过顶部状态栏文字反馈：

| 阶段 | 状态栏文字 |
|---|---|
| 检查中 | 正在检查更新 |
| 发现新版本 | 发现新版本 自动更新中 |
| 下载 / 覆盖中 | 更新中，请稍候 |
| 更新完成 | 已更新至最新版 |
| 更新失败 | 网络错误，正在自动重试 |

失败不会中断 —— 后台会按退避策略换线继续，直到成功为止。

## 国内网络说明

原版直连 `api.github.com` 在国内无法建立连接。实测结果：

| 访问地址 | 直连 | 走 `gh-proxy.com` |
|---|---|---|
| `api.github.com/.../releases/latest` | `code=000`（0.02s 即失败） | `code=200`，1.07s |
| `github.com/.../releases/download/...` | `code=000` | `code=200`，1.01s |

这是「网络错误」提示的真正原因 —— 并非设备网络故障，而是相关域名在国内直连被拒。
它同时是此前「点击更新按钮闪退」的根因：连接异常被包装成业务异常后，
在后台线程顶层重新抛出，直接导致进程崩溃。

**自动更新版**的对应修复：

- `C4.d()`：查询地址改为 `https://gh-proxy.com/https://api.github.com/...`
- `C4.h()`：下载 URL 在**通过原有白名单校验之后**追加 `gh-proxy.com` 前缀
  - 顺序很关键。若反过来，`URL.getHost()` 会变成 `gh-proxy.com`，
    会被判定为非信任域名并抛出 `Untrusted release asset URL`。
  - 白名单常量本身**未放宽**，安全性不降级。
- SHA-256 与文件大小校验逻辑**原样保留**。代理只替换 URL，不改动数据字节。

**不更新版**则是直接移除联网入口：

- `C4.b()` —— 唯一的联网线程启动出口，整段删除改为直接返回。
  封死这个出口后，上层 `a()` 的全部联网路径自动失效，无需逐处修改调用点。
- `G3` 的 `case 2`（启动 1.8 秒后的延时自动检查）直接返回。
- `m2` 的**全部 5 个状态分支**均不再传递按钮文字，只显示状态标题，
  进入后直接呈现「已是最新版」。

**按钮的隐藏**：

`MainActivity.h(title, btnText, enabled, highlight)` 是统一的状态栏刷新方法，
其中「按钮文字为空串则设为 `View.GONE`」的判断让按钮**真正从布局中移除**。
自动更新版的按钮**在布局构建阶段就已整块删除**，字段 `g` 恒为 `null`，
`h()` 内部对 `g` 的 `if-eqz` 守卫使相关代码全部空转 —— 界面上不存在任何可点的更新控件。

## 崩溃兜底

两版均内置 `DG` / `DGH`，在启动检查前安装全局未捕获异常处理器。
万一出现未预料的异常，会弹窗显示崩溃详情并把日志写入：

```
Android/data/com.majsoul/files/dg.log
```

而不是让应用无声消失。遇到问题请把该日志或崩溃截图反馈到 Issues。

## 源码结构

本仓库是 APK 的反编译产物（smali），改动集中在以下几个文件：

| 文件 | 作用 |
|---|---|
| `smali/q/C4.smali` | 更新逻辑：查询、下载、校验、线路前缀改写 |
| `smali/q/m2__dup2.smali` | UI 状态分发与更新执行体 |
| `smali/q/w4__dup2.smali` | 检查线程，失败分支接入自动重试 |
| `smali/q/G3.smali` | 启动延时任务 |
| `smali/q/C3.smali` | 更新对话框处理（按钮已移除，相关分支不可达） |
| `smali/q/DGLines.smali` | 线路池与环形轮换 |
| `smali/q/DGRetry.smali`、`DGRetry$1.smali` | 无限重试调度器（指数退避 + 代际防过期） |
| `smali/q/DGStart.smali` | 冷启动门控（仅进程首启触发一次） |
| `smali/q/DG.smali`、`smali/q/DGH.smali` | 崩溃捕获与日志 |

> 注：文件名中的 `__dup2` 后缀是 Windows 大小写不敏感导致的落地命名，
> 类名本身唯一，不影响回编。
